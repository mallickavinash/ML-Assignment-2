# ML Assignment 2: Bot and User Classification

## Problem Statement

The objective of this project is to automatically distinguish between bot accounts and human user accounts using profile and activity-related features from a social-network dataset. The task is treated as a **binary classification problem**:

- `0` = human/user account
- `1` = bot account

Five supervised machine-learning classifiers are trained and compared:

1. Logistic Regression
2. Decision Tree
3. K-Nearest Neighbors (KNN)
4. Gaussian Naive Bayes
5. Support Vector Machine (SVM)

The trained models are evaluated using accuracy, AUC, precision, recall, F1-score, and Matthews correlation coefficient (MCC). A Streamlit application provides an interactive interface for uploading test data, selecting a trained model, viewing performance metrics, inspecting predictions, and comparing all models.

## Dataset Description

The project uses the [Bots vs Users dataset](https://www.kaggle.com/datasets/yesiamma/bots-vs-users-dataset?select=bots_vs_users.csv), with `target` as the class label.

### Dataset summary

| Property | Value |
|---|---:|
| Total records | 5,874 |
| Total columns | 60 |
| Feature columns | 59 |
| Target column | `target` |
| Human class (`0`) | 2,937 records |
| Bot class (`1`) | 2,937 records |
| Missing values | 62,762 |

The dataset is balanced between the two classes. It contains numeric profile/activity measurements and categorical profile attributes. Features include profile completeness indicators, account verification flags, interaction counts, posting activity, content characteristics, demographic fields, and other account metadata.

In this repository, the data preparation and model-training steps use:

- Missing values handled during model preprocessing
- Median imputation for numeric features
- Most-frequent imputation for categorical features
- Standard scaling for numeric features
- One-hot encoding for categorical features
- An 80/20 stratified train-test split
- Random state of 42 for reproducibility

The 20% held-out test set is saved as `test_data.csv`. The encoded label mapping and the list of expected feature columns are saved in `model/meta.joblib`.

## Models Used

All models are implemented through scikit-learn pipelines. Preprocessing is fitted within each pipeline, allowing raw test data to be passed directly to the trained model.

### 1. Logistic Regression

Logistic Regression is a linear baseline model that estimates the probability of each class. Its coefficient-based structure also provides a useful reference point for interpretable classification.

### 2. Decision Tree

A Decision Tree makes classification decisions through feature-value rules. The implementation uses a fixed random state to make the model reproducible.

### 3. K-Nearest Neighbors (KNN)

KNN assigns a class based on the five nearest training examples. Numeric features are scaled before distance calculation, and categorical features are one-hot encoded.

### 4. Gaussian Naive Bayes

Gaussian Naive Bayes applies Bayes' theorem under a conditional-independence assumption. It assumes that continuous feature values follow Gaussian distributions.

### 5. Support Vector Machine (SVM)

The SVM learns a decision boundary that maximizes separation between the classes. This project uses an RBF-capable SVM classifier with probability estimates enabled, which also allows the application to calculate ROC-AUC.

## Evaluation Metrics

The following metrics are calculated on the held-out test set.

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---:|---:|---:|---:|---:|---:|
| Logistic Regression | 0.9711 | 0.9935 | 0.9792 | 0.9625 | 0.9708 | 0.9423 |
| Decision Tree | 0.9626 | 0.9599 | 0.9738 | 0.9506 | 0.9621 | 0.9254 |
| KNN | 0.9523 | 0.9790 | 0.9554 | 0.9489 | 0.9521 | 0.9047 |
| Naive Bayes | 0.6757 | 0.6763 | 0.6117 | 0.9608 | 0.7475 | 0.4281 |

The values are generated by `main.py` and stored in `model/metrics_table.csv`. Accuracy measures the proportion of total correct predictions, AUC measures class-ranking quality, precision measures how many predicted bot accounts were actually bots, recall measures how many actual bots were detected, F1 balances precision and recall, and MCC measures overall correlation between predicted and actual classes.

## Model Performance Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | The strongest overall model. It achieved the highest accuracy, AUC, precision, recall, F1-score, and MCC while remaining computationally efficient and easy to deploy. |
| Decision Tree | Performed well with 96.26% accuracy, but its lower AUC indicates less reliable probability ranking than Logistic Regression and SVM. It may capture simple rules but is more susceptible to overfitting than the ensemble-free linear model. |
| KNN | Produced balanced but lower results than Logistic Regression, Decision Tree, and SVM. Performance depends on local distance structure and scaling, so it may be less efficient and robust on larger datasets. |
| Naive Bayes | Had the highest recall among all models at 96.08%, meaning it detected most bots, but its precision of 61.17% was poor. Its many false positives and low overall accuracy make it unsuitable as the winning standalone model for this task. |
| Support Vector Machine | Strong and close to Logistic Regression across every metric. Its 98.94% AUC and 96.43% accuracy show excellent discrimination, although prediction and probability estimation are more computationally expensive than Logistic Regression. |
| **Overall winner** | **Logistic Regression.** It achieved the best result in every metric on the recorded test split and provided the best balance of discrimination and classification quality. |

### Metric conclusions

- Logistic Regression is recommended for deployment because it is the strongest overall model and is faster and simpler than SVM.
- SVM is the closest alternative and is worth considering if nonlinear decision boundaries are required.
- Naive Bayes should not be selected despite its high recall because it has substantially lower precision and accuracy.
- Model performance should be revalidated with a separate real-world holdout set because the reported values are based on a single stratified split.

5. Run the optional on-demand comparison across all five models.

The dashboard expects every feature column listed in `model/meta.joblib` and a `target` column containing labels known to the training label encoder.
